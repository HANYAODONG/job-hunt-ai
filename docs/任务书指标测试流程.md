# 任务书指标测试流程

## 1. 测试目标

本流程用于复现任务书要求的三项核心指标：

| 指标 | 硬性标准 | 本次测试规模 |
| --- | ---: | ---: |
| JD解析准确率（Micro-F1） | ≥90% | 400条JD |
| 简历提取准确率（Micro-F1） | ≥90% | 400份简历 |
| 人岗匹配准确率（Accuracy） | ≥90% | 400组匹配样本 |

金标目录为`artifacts/taskbook_gold_v2_400/`。该数据最初由Codex辅助预标，随后经项目小组人工审核确认并冻结。审核记录见`human_review_approval_manifest.json`。

## 2. 测试原则

1. 测试前后不得修改三个`*_annotation_adjudicated.csv`金标文件。
2. 不得根据模型预测结果反向调整金标。
3. 匹配指标必须使用5折折外预测，不能直接报告训练集准确率。
4. 每次测试必须记录Git提交、数据哈希、模型名称、测试命令和结果文件。
5. 测试人员不要运行`prefill_taskbook_gold.py`或`approve_taskbook_gold.py`，这两个脚本用于生成或批准金标，不属于日常测试流程。

## 3. 环境准备

在PowerShell中进入项目根目录：

```powershell
cd "项目所在位置\job-hunt-ai-backend-integration"
```

检查基础环境：

```powershell
git rev-parse HEAD
py --version
docker --version
docker compose version
```

首次部署或代码、依赖发生变化时运行：

```powershell
docker compose up -d --build
```

已经构建过镜像时运行：

```powershell
docker compose up -d
```

确认四个服务正常：

```powershell
docker compose ps
```

应看到Elasticsearch、Neo4j、backend和frontend处于运行状态，其中backend最终应为`healthy`。

## 4. 检查测试数据

```powershell
Test-Path artifacts\taskbook_gold_v2_400\jd_annotation_adjudicated.csv
Test-Path artifacts\taskbook_gold_v2_400\resume_annotation_adjudicated.csv
Test-Path artifacts\taskbook_gold_v2_400\matching_annotation_adjudicated.csv
Test-Path artifacts\taskbook_gold_v2_400\human_review_approval_manifest.json
Test-Path artifacts\dataset_iteration_05\jobs.jsonl
Test-Path artifacts\dataset_iteration_05\candidate_profiles.jsonl
```

以上命令都应返回`True`。然后检查审核状态：

```powershell
$approval = Get-Content -Raw -Encoding UTF8 `
  artifacts\taskbook_gold_v2_400\human_review_approval_manifest.json | ConvertFrom-Json

$approval.status
$approval.formal_acceptance_eligible
$approval.rows
```

应满足：

- `status`为`human_review_approved`
- `formal_acceptance_eligible`为`True`
- JD、简历、匹配均为400条

## 5. 后端回归测试

单元测试在本机Python环境执行。首次运行缺少依赖时安装：

```powershell
py -m pip install -r backend-src\requirements.txt
py -m pip install pytest pytest-cov
```

执行测试：

```powershell
cd backend-src
py -m pytest tests -q --disable-warnings
cd ..
```

当前版本预期结果为`105 passed`。如果存在失败项，应先修复回归问题，再运行指标测试。

## 6. 人岗匹配5折评估

BGE模型依赖在Docker后端容器中执行。模型已经缓存时使用离线模式：

```powershell
docker compose exec -T `
  -e HF_HUB_OFFLINE=1 `
  -e TRANSFORMERS_OFFLINE=1 `
  backend python scripts/evaluate_taskbook_matching_cv.py `
  --gold-dir /app/artifacts/taskbook_gold_v2_400 `
  --output-dir /app/artifacts/taskbook_acceptance_20260830/matching_bge_role_gate_cv_400
```

如果首次运行提示模型不存在，联网下载一次：

```powershell
docker compose exec -T `
  -e HF_HUB_OFFLINE=0 `
  -e TRANSFORMERS_OFFLINE=0 `
  -e HF_ENDPOINT=https://huggingface.co `
  backend python scripts/evaluate_taskbook_matching_cv.py `
  --gold-dir /app/artifacts/taskbook_gold_v2_400 `
  --output-dir /app/artifacts/taskbook_acceptance_20260830/matching_bge_role_gate_cv_400
```

该步骤会生成：

- `matching_bge_role_gate_cv_400/cv_report.json`
- `matching_bge_role_gate_cv_400/oof_predictions.csv`

检查匹配结果：

```powershell
$cv = Get-Content -Raw -Encoding UTF8 `
  artifacts\taskbook_acceptance_20260830\matching_bge_role_gate_cv_400\cv_report.json | ConvertFrom-Json

$cv | Select-Object samples,folds,accuracy,precision,recall,f1,meets_taskbook_90_percent_accuracy
```

必须满足：

- `samples=400`
- `folds=5`
- `accuracy≥0.90`
- `meets_taskbook_90_percent_accuracy=True`

## 7. 汇总三项正式指标

匹配折外预测生成后，运行统一评估：

```powershell
py scripts\evaluate_taskbook_gold.py `
  --gold-dir artifacts\taskbook_gold_v2_400 `
  --matching-predictions artifacts\taskbook_acceptance_20260830\matching_bge_role_gate_cv_400\oof_predictions.csv `
  --output artifacts\taskbook_acceptance_20260830\human_gold_metrics_400.json
```

查看最终结果：

```powershell
$metrics = Get-Content -Raw -Encoding UTF8 `
  artifacts\taskbook_acceptance_20260830\human_gold_metrics_400.json | ConvertFrom-Json

[pscustomobject]@{
  FormalEligible    = $metrics.formal_acceptance_eligible
  JD_F1             = $metrics.jd_parsing.skill_micro.f1
  Resume_F1         = $metrics.resume_extraction.skill_micro.f1
  MatchingAccuracy  = $metrics.matching.model_scores.accuracy
  MatchingF1        = $metrics.matching.model_scores.f1
} | Format-List
```

当前冻结版本的预期结果：

| 指标 | 预期值 | 判定 |
| --- | ---: | --- |
| `formal_acceptance_eligible` | `True` | 金标可用于正式验收 |
| JD技能解析Micro-F1 | 0.944510 | 达标 |
| 简历技能提取Micro-F1 | 0.947257 | 达标 |
| 简历经验年限准确率 | 1.000000 | 达标 |
| 人岗匹配Accuracy | 1.000000 | 达标 |
| 人岗匹配F1 | 1.000000 | 达标 |

结果允许因明确的代码或数据版本升级发生变化，但三项硬指标不得低于0.90。出现变化时必须记录新的Git提交和文件哈希，不能直接覆盖原测试记录。

## 8. 接口烟雾测试

检查后端健康状态：

```powershell
Invoke-RestMethod http://localhost:18088/health
```

测试真实融合推荐接口：

```powershell
$body = @{
  candidate_id  = "resume_000001_exp00_0"
  mode          = "sample"
  top_k         = 10
  candidate_pool = 50
} | ConvertTo-Json

$response = Invoke-RestMethod `
  -Method Post `
  -Uri http://localhost:18088/api/v1/fusion/recommend `
  -ContentType "application/json" `
  -Body $body

$response.results | Select-Object rank,job_id,final_score,@{
  Name="job_family_match"
  Expression={$_.score_breakdown.job_family_match}
} | Format-Table
```

接口应返回HTTP 200、至少一条推荐结果，并显示0至1之间的`job_family_match`。当前岗位族模型常见取值为`1.0`（同岗位）、`0.8`（同族）、`0.4`（相邻族）和`0.0`（跨族）。

## 9. 测试结果提交

测试人员应提交以下内容：

1. 测试日期、测试人和Git提交ID。
2. `docker compose ps`截图或文本。
3. 单元测试通过数量。
4. `human_gold_metrics_400.json`。
5. `matching_bge_role_gate_cv_400/cv_report.json`。
6. 测试失败时的完整命令、报错和后端日志。

查看后端日志：

```powershell
docker compose logs --tail=200 backend
```

## 10. 测试结束

不再使用服务时停止容器：

```powershell
docker compose down
```

该命令不会删除持久化数据卷。不要附加`-v`，否则会同时删除Elasticsearch和Neo4j的数据卷。
