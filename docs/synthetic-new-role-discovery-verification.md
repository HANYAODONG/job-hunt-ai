# 新岗位发现功能验证记录

## 验证目的

验证系统面对一批不能稳定归入当前三级岗位池的新增 JD 时，能够完成保守路由、同类聚类、阈值判断和人工审核入队，而不会自动污染正式岗位池。

## 输入

- 测试批次：`artifacts/discovery_synthetic_fixture/synthetic_new_role_jds.csv`
- 数据性质：功能验证用合成 JD，不作为真实市场岗位或历史演化证据。
- 输入数量：12 条。
- 统一岗位标题：边缘智能体编排工程师。
- 测试月份：2026-08。
- 关键职责：端云协同、端侧智能体任务编排、工具调用、任务状态机、设备协同、故障回退与审计。

## 规则

1. 新 JD 先与当前标准三级岗位目录进行保守路由。
2. 未稳定归类的 JD 保留原始岗位 ID、标题、职责和要求，进入审核队列。
3. 按候选岗位标题聚类，并按独立 JD ID 去重计数。
4. 去重后的同类 JD 数量大于 10 时，进入人工审核，不自动发布新三级岗位。
5. 只有审核人员补充岗位边界、二级方向与 `canonical_role_id` 并确认发布后，岗位才能进入正式池。

## 实际结果

| 项目 | 结果 |
|---|---:|
| 输入 JD | 12 |
| 路由结果 | 12 条均为 `potential_new_job` |
| 未归类 JD | 12 |
| 候选聚类 | 1 个：边缘智能体编排工程师 |
| 独立 JD 证据 | 12 |
| 触发门槛 | 大于 10 |
| 是否满足门槛 | 是 |
| 候选状态 | 待人工审核 |
| 正式岗位池变更 | 否 |

## 前端操作

1. 打开“岗位演化中心”。
2. 进入“批量新岗位发现”。
3. 点击“验证新岗位发现”。
4. 页面显示候选岗位、支撑 JD 数、路由结果和“正式池变更：无”。

该验证接口每次使用独立的 `artifacts/discovery_synthetic_fixture/runs/` 运行目录，不写入 `company_large_v2` 的事件流、标准岗位字典或正式 SQLite 数据库。
