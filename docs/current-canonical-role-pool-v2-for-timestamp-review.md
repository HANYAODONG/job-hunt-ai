# 当前三级岗位池（v2）首现月份审查表

> 本表来自当前 `canonical_role_pool_v2` 运行池，供人工核查哪些岗位不应在早期月份出现。
> 岗位池的三级层级为：一级方向 = `domain`，二级方向 = `direction`，三级岗位 = `role_name`。
> 当前事件流的月份用于版本回放和月度比较；在完成逐岗位核查前，不能把它当作真实市场首发日期。

## 当前版本概览

- 岗位身份：78 个（active 76，review-only 2）。
- 正式 JD 输入：11361 条；仅 active 岗位进入正式输入。
- 事件流覆盖月份：2024-12 至 2026-07；现状是首月已覆盖全部 73 个历史标准标签，因此本表重点是人工补充可信的岗位首现月份。
- `canonical_role_id` 是系统稳定身份键；岗位名称可以调整，但不要为同一岗位重复创建身份键。

## 人工填写规则

1. 只在“人工确认首现月份”填写 `YYYY-MM`；无法确认时留空，不要猜测。
2. 判断对象是现实中岗位身份首次有可靠 JD 证据的月份，而不是某条 JD 被均分到事件流的月份。
3. “依据/备注”填写公开招聘平台、企业招聘页、行业报告或数据组的原始采集说明；若只有经验判断，请明确写“待核查”。
4. 首现月份确认后，再由脚本按岗位身份回填事件流；回填必须保留原文件备份和变更审计。
