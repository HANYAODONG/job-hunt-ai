# 第五轮分工：前端真实对接与全链路可用性收口

## 1. 本轮背景

上一轮已经完成了多个工作流 PR 的合并，后端也已经具备了 BM25、语义重排、知识图谱分析、融合排序、简历诊断、JD 更新等基础能力。现在项目的主要矛盾不是“有没有模块”，而是：

- 组长提交的新前端页面已经存在，但部分页面仍然使用 Mock 数据。
- 后端已有不少接口，但前端还没有完全接到真实接口上。
- 不同工作流产物已经合并，但还需要通过网页把完整流程跑通。
- 甘可欣负责的企业端岗位索引、候选人数据出口、BM25 支撑仍有遗留，本轮继续作为遗留任务推进，不阻塞其他页面先做对接。

因此，本轮主线是：

```text
前端页面逐个检查
  -> 确认当前调用的 service
  -> 能接真实接口的先接真实接口
  -> 缺后端接口的写清楚缺口
  -> 页面按钮、表格、图谱、卡片都能正常展示
  -> 最后完成网页级测试
```

## 2. 本轮总目标

让组长前端成为项目最终展示前端，尽快从“页面能打开”推进到“功能能使用、数据能流动、缺口能解释”。

本轮完成后，至少要达到：

1. 前端主要页面可以稳定启动和访问。
2. `/fusion-demo`、`/diagnosis`、`/search`、`/recommendations` 优先接入真实推荐链路。
3. `/signals` 尽量接入 JD 更新和岗位市场数据。
4. `/graph` 明确动态图谱接口和最小可运行版本。
5. `/learning` 明确学习路径生成逻辑，能接则接，不能接则留缺口文档。
6. `/recruitment`、`/candidates` 先不强行卡住主线，甘可欣继续补遗留数据出口。
7. 所有仍使用 Mock 的地方必须在文档中标明原因、缺少接口、后续负责人。

## 11. 本轮完成标志

本轮不是以“所有模型都训练完成”为结束标准，而是以前端能否正常展示项目能力为准。

完成标志：

1. 前端可以稳定启动。
2. 每个主要页面都能打开。
3. 核心推荐流程可以通过网页触发。
4. 至少一条完整链路跑通：

```text
上传或选择简历
  -> 召回岗位
  -> 语义重排
  -> 技能/图谱分析
  -> 融合排序
  -> 前端展示推荐结果和解释
```

5. 图谱、市场信号、学习路径至少有最小可展示版本或明确接口缺口。
6. 所有 Mock 页面都有说明，不再出现“看起来能点但不知道数据从哪来”的情况。
7. main 分支保持可部署、可测试、可继续迭代。
