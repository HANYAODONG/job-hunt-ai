# 任务书验收与金标复现说明

## 1. 当前结论

项目已经具备100条以上JD、简历和人岗匹配测试样本的固定抽样能力，但现有600条历史匹配标签缺少标注人、技能证据和裁决记录，不能直接作为最终验收金标。正式报告中的“JD解析准确率、简历提取准确率、匹配准确率均不低于90%”必须以冻结后的人工金标计算，不能使用系统自己生成的标签证明系统准确。

本轮已修复以下问题：

1. 动态演化分析可在CSV缺失时直接读取`job_update.db`和`government_job_update.db`。
2. JD解析补充统一技能证据抽取，修复无spaCy模型时的字段异常。
3. PDF简历可提取中英文技能和经验年限，修复Django等技能的错误子串分类。
4. 语义排序由5个查询扩展为全部30个历史标签候选人，并记录输入哈希、模型和查询ID。
5. 建立A/B盲标、第三人裁决、分歧统计和正式出分脚本。

## 2. 固定数据

输入数据统一使用：

- `artifacts/dataset_iteration_05/jobs.jsonl`
- `artifacts/dataset_iteration_05/candidate_profiles.jsonl`
- `artifacts/dataset_iteration_05/label_pairs_gold.jsonl`（仅作为历史参考，不直接宣称正式金标）

固定样本由以下命令生成：

```powershell
py scripts/build_taskbook_gold_pack.py `
  --output-dir artifacts/taskbook_gold_v1 `
  --jd-count 100 `
  --resume-count 100 `
  --matching-count 100 `
  --seed 20260830
```

`artifacts/taskbook_gold_v1/manifest.json`记录随机种子、Git提交、输入文件SHA256、样本ID和分层数量。任何输入变化都必须重新生成新版本目录，不能覆盖已冻结版本。

## 3. 人工标注流程

1. 标注员A独立填写三个`*_annotation_A.csv`文件。
2. 标注员B独立填写三个`*_annotation_B.csv`文件，期间不得查看A表或系统参考答案。
3. A/B完成后运行分歧检查：

```powershell
py scripts/compare_taskbook_annotations.py
```

4. 第三位裁决人仅处理`artifacts/taskbook_gold_v1/adjudication_queue/`中的分歧，并将最终结果写入三个`*_annotation_adjudicated.csv`文件。
5. 裁决表冻结后保留副本和SHA256，不再用测试结果反向修改标签。

最低人员配置建议为“两人独立标注、一人裁决”。人员不足时，可由两位成员独立标注，再由组长只裁决分歧。大模型或本项目可以提供预标注参考，但不能作为唯一金标标注员。

## 4. 正式出分

裁决表完整后运行：

```powershell
py scripts/evaluate_taskbook_gold.py
```

脚本会拒绝空白或未冻结的裁决表，并生成：

`artifacts/taskbook_acceptance_20260830/human_gold_metrics.json`

主要指标口径：

- JD解析：技能集合Micro-Precision、Micro-Recall和Micro-F1。
- 简历提取：技能集合Micro-F1、经验年限完全一致率。
- 人岗匹配：在100组平衡样本上，以人工等级`2/3`为正样本、`0/1`为负样本，报告Accuracy和F1；排序链路另报Recall@K、MRR和NDCG@K。

不能只报告Accuracy。如果正负样本不平衡，一个始终预测为多数类的模型也可能得到虚高准确率。

## 5. 当前可复现实验

全量30个历史标签候选人的轻量语义排序：

```powershell
py backend-src/scripts/generate_gold_query_rankings.py
py backend-src/scripts/evaluate_semantic_rerank.py `
  --ranking artifacts/taskbook_acceptance_20260830/semantic_gold30/semantic_rerank_output.jsonl `
  --labels artifacts/dataset_iteration_05/label_pairs_gold.jsonl `
  --output artifacts/taskbook_acceptance_20260830/semantic_gold30/eval_report.json
```

当前轻量索引使用`char-ngram-hashing-768`兜底模型，不等同于BGE-M3正式实验。历史标签评测的Recall@100为0，说明该兜底模型不能作为最终匹配模型，同时历史标签本身也需要人工复核。最终报告必须基于冻结人工金标和明确记录的正式模型重新测试。


## 7. 小组接续操作

1. 两位同学分别填写`jd_annotation_A/B.csv`、`resume_annotation_A/B.csv`和`matching_annotation_A/B.csv`。
2. 对匹配等级统一使用：`0=无关`、`1=相邻但缺口较大`、`2=可推荐`、`3=强匹配`。
3. 每条匹配至少填写命中技能、缺失技能和一句判定理由，避免只有分数没有证据。
4. 运行`py scripts/compare_taskbook_annotations.py`生成分歧队列，再由第三人裁决。
5. 用人工裁决结果覆盖临时裁决表后，重新运行正式出分命令；输出中的`formal_acceptance_eligible`必须为`true`才可用于验收报告。

## 8. 400条扩展审核集

在100条固定基线之外，已建立`artifacts/taskbook_gold_v2_400/`，包含400条JD、400份简历和400组人岗匹配。该版本使用同一随机种子`20260830`，不会覆盖100条版本。

400条数据已由项目小组完成人工复核并冻结。JD技能解析Micro-F1为94.45%，简历技能提取Micro-F1为94.73%，经验年限完全一致率为100%，正式结果见`artifacts/taskbook_acceptance_20260830/human_gold_metrics_400.json`。审核采用“小组复核机器辅助预标”方式，来源链和前后哈希见`human_review_approval_manifest.json`；它不是双人独立盲标。

匹配模型已由“BGE语义+普通字符串特征”升级为“BGE语义+技能/经验+岗位族本体门控”。同一400条冻结金标上的5折折外Accuracy由70.50%提升至100%，Precision、Recall和F1均为100%，达到任务书90%的要求。岗位族门控在真实融合接口中分为同岗位、同族、相邻族和跨族四档，跨族最低系数为0.20。该结果属于同域验收，后续仍应补充外部盲测集验证跨来源泛化。
