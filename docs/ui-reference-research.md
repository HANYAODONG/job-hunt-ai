# 岗位能力图谱工作台 UI 参考研究

研究对象：`XH-202621 多源异构数据驱动岗位和能力图谱构建与动态演化分析研究` 前端工作台。

访问日期：2026-07-25（页面以官方站点当前内容为准）。

研究范围：岗位发现、能力图谱、岗位演化、人岗诊断、数据治理、评测中心所需的工作台布局、导航、信息密度、数据表格、图谱画布和状态色。以下均为产品方或设计系统方的一手资料，不把二手“灵感合集”当作规范来源。

## 先看哪些

建议先按这个顺序打开页面：

1. [Palantir Foundry Vertex](https://www.palantir.com/docs/foundry/vertex/overview/)：看对象关系图谱如何与筛选、详情、保存协作结合。
2. [Gephi Quickstart](https://gephi.org/quickstart/)：看图谱画布、布局算法、节点/边样式和底部渲染控制。
3. [IBM Carbon Data table](https://carbondesignsystem.com/components/data-table/usage/)：看高密度治理表格的工具栏、筛选、分页、可展开行。
4. [Grafana Build dashboards](https://grafana.com/docs/grafana/latest/dashboards/build-dashboards/)：看可配置仪表盘的变量、面板复用、注释和链接。
5. [Atlassian Navigation system](https://atlassian.design/components/navigation-system)：看企业工作台的侧边导航分组和层级收纳。
6. [Atlassian Color](https://atlassian.design/foundations/color)：看语义色、token 和数据可视化色板的分工。
7. [Ant Design Layout](https://ant.design/components/layout/)：看 Header/Sider/Content、可收起侧栏、固定头部和响应式布局。

## 参考一：Palantir Foundry Ontology / Vertex

- 官方页面：[Ontology overview](https://www.palantir.com/docs/foundry/ontology/overview/)、[Vertex overview](https://www.palantir.com/docs/foundry/vertex/overview/)、[Object Explorer overview](https://www.palantir.com/docs/foundry/object-explorer/overview/)
- 可观察到的结构：Foundry 把对象类型、属性和链接组织成可操作的 Ontology；Vertex 文档明确覆盖图的创建、对象与边的显示选项、保存/分享/协作，以及图中的搜索、过滤和布局。Object Explorer 同时提供搜索、过滤、图表、结果列表和关联对象探索。
- 对本项目的借鉴：
  - 将“岗位”“能力节点”“技能证据”“行业/区域”等视为统一对象，关系边用于“岗位需要能力”“能力属于族群”“证据支持能力”等，不要把图谱做成单独的装饰页。
  - 图谱右侧保留对象详情抽屉，左侧提供筛选/图层，顶部保留保存视图、分享和回到上次探索等工作流动作。
  - 岗位发现和诊断结果可复用同一个对象检视器：列表、关联对象、时间变化、可执行动作在同一上下文中切换。
- 风险/不应照搬：Foundry 的对象模型和权限系统非常重，不能在前端复制一套平台；本项目只需要稳定的对象/关系展示契约和 mock 状态。避免把所有页面都变成“图+抽屉”，列表任务仍应优先使用表格。

## 参考二：Gephi 图谱工作台

- 官方页面：[Gephi Quickstart](https://gephi.org/quickstart/)
- 可观察到的结构：导入 `Source`/`Target` 两列即可生成网络；Overview 视图把图谱画布、数据表、过滤器和布局工具放在同一工作区。官方教程提到可用 ForceAtlas 2 进行空间布局，通过选择工具移动节点、给节点着色、控制边粗细和标签显示；数据表可排序、筛选列，Filters 面板支持按节点属性过滤。
- 对本项目的借鉴：
  - 图谱页采用“画布 + 控制台 + 详情”的三栏关系：画布占主空间，左侧控制节点/边和布局，右侧显示选中岗位或能力的属性与证据。
  - 画布工具只保留选择、拖动、缩放、适配视图、标签开关、布局切换；把复杂参数收在可展开面板，不让工具栏占据首屏。
  - 节点颜色表达节点类型，大小表达一个稳定指标（如岗位热度或能力覆盖度），边颜色/粗细表达关系强度；提供图例和“恢复默认样式”。
- 风险/不应照搬：ForceAtlas 2 的参数和自由拖拽适合分析软件，不适合普通业务用户。不要把算法参数暴露成一长串表单，也不要用高饱和彩虹色同时编码多个维度；默认图必须可读、可回退。

## 参考三：IBM Carbon Design System 数据表

- 官方页面：[Data table usage](https://carbondesignsystem.com/components/data-table/usage/)
- 可观察到的结构：Carbon 将数据表定义为高效组织和展示数据的组件，支持选择、展开、编辑、斑马纹、分页；表格工具栏提供主操作、搜索、过滤、显示设置和其他工具；Compact 变体用于在小空间展示大量数据；行面板可展开/收起附加信息。
- 对本项目的借鉴：
  - 数据治理、岗位审核、评测记录默认采用紧凑表格，表头工具栏固定放搜索、筛选、列设置、批量操作和刷新时间。
  - “行内摘要 + 展开详情”适合展示岗位来源、能力证据、质量问题和评测解释，不必强制跳转页面。
  - 批量选择、分页、空状态、加载状态和失败状态应在 mock 页面中一并预留，避免只有一张静态表。
- 风险/不应照搬：Carbon 的密度和 IBM 产品语境偏企业级，不应把所有页面缩成 12px 字号；治理表可以高密度，首页 KPI 和图谱详情仍需要呼吸感。

## 参考四：Grafana Dashboard

- 官方页面：[Build dashboards](https://grafana.com/docs/grafana/latest/dashboards/build-dashboards/)
- 可观察到的结构：官方文档把仪表盘拆为创建、模板/建议、筛选与分组、导入、设置、链接、URL 变量、Library panels、版本历史、可视化注释和最佳实践等能力；核心是可组合面板，而不是单一大图。
- 对本项目的借鉴：
  - 首页使用“结论面板”而不是平均分配的 KPI 卡：岗位新增、能力覆盖、待审核、数据健康分别对应趋势、异常和下一步动作。
  - 为行业、时间范围、岗位族群、数据来源提供全局筛选变量；筛选条件在岗位发现、演化和诊断页之间保持可见、可复用。
  - 图表面板要支持“查看明细”“打开图谱”“进入审核队列”等链接；常用的质量趋势、来源分布、能力缺口面板可做可复用组件。
  - 版本/更新时间、注释和数据延迟要以轻量状态显示，帮助用户判断数据是否新鲜。
- 风险/不应照搬：Grafana 面向监控运维，时间序列和告警密度很高。岗位情报页面不能塞满折线图，也不应把所有状态都做成红黄绿告警；只有需要行动的异常才用强调色。

## 参考五：Atlassian Design Navigation system

- 官方页面：[Navigation system](https://atlassian.design/components/navigation-system)
- 可观察到的结构：官方导航体系包含侧边导航、面包屑、菜单、链接、页面头部等独立组件，并把导航与可访问焦点、层级收纳和响应式行为一起定义；同一设计系统还把 Dynamic table、Table tree、Page header 归入配套组件。
- 对本项目的借鉴：
  - 侧栏分为“核心工作流”和“治理与交付”两组；每项带图标、当前态和可收起的子项，不要把所有入口平铺。
  - 页头只显示当前模块、当前数据范围和一到两个主动作；详情页用面包屑或返回入口维持上下文。
  - 移动端侧栏采用抽屉/覆盖层，内容区全宽；桌面端允许收起到图标栏，保留 tooltip 和当前态标记。
- 风险/不应照搬：Atlassian 的产品通常有多产品切换和复杂权限，导航层级可能比本项目深。项目入口最多两层，超过两层应改为页内 tabs、筛选或详情抽屉。

## 参考六：Atlassian Design Color

- 官方页面：[Color overview](https://atlassian.design/foundations/color)
- 可观察到的结构：页面将颜色拆为品牌/界面颜色、颜色 token、无障碍、强调色、颜色选择器和数据可视化色板，并强调颜色承担区分品牌、状态和数据类别的角色，而不是单纯装饰。
- 对本项目的借鉴：
  - 先定义中性界面色（画布、面板、边框、主文字、次文字），再定义语义色（成功、警告、风险、信息）和数据类别色（岗位、能力、证据、来源）。
  - 同一语义在按钮、标签、图表和图谱节点使用同一 token；不要每个页面自行挑一套绿/蓝。
  - 状态不能只靠颜色：标签配合文字/图标，图谱配合图例和形状/边型，满足色觉差异和打印/截图场景。
- 风险/不应照搬：Atlassian 的品牌紫、蓝和红不能直接成为本项目主色。建议以中性灰白为底、低饱和青绿作主行动色，靛蓝/珊瑚/金色只做明确语义强调，并控制同时出现的强调色数量。

## 参考七：Ant Design Layout

- 官方页面：[Layout](https://ant.design/components/layout/)
- 可观察到的结构：官方 Layout 组件直接覆盖 Header-Content-Footer、Header-Sider、可收起 Sider、Overlay、Responsive、Fixed Header 等结构，适合把工作台壳层和业务内容分离。
- 对本项目的借鉴：
  - 保留固定 Header + 可收起 Sider + 滚动 Content 的壳层；头部显示系统名、当前赛题/数据快照和用户入口。
  - 桌面端 Sider 使用稳定宽度和独立滚动，内容区保持统一最大宽度；小屏幕切换为 Overlay，关闭后内容占满 viewport。
  - 页面内部用 Grid/Flex 分配面板，不用嵌套大量 Card；只有需要边界、阴影或操作聚焦的重复项才使用卡片。
- 风险/不应照搬：组件示例的默认蓝色、圆角和 Card 组合不等于产品视觉。Layout 只解决空间关系，颜色、字体、密度和业务层级需要单独定义。

## 参考八：Palantir Foundry Object Explorer

- 官方页面：[Object Explorer overview](https://www.palantir.com/docs/foundry/object-explorer/overview/)
- 可观察到的结构：官方文档列出搜索对象、按语法检索、使用 SQL 分析、按图表查看、过滤结果、探索关联对象、比较对象集合、保存探索、应用 Actions 等连续动作。
- 对本项目的借鉴：
  - 岗位发现结果页应支持“筛选 -> 比较 -> 查看关联能力 -> 进入诊断 -> 保存视图”的连续路径，避免用户在多个独立页面之间手工搬运岗位 ID。
  - 比较视图至少预留岗位基本信息、能力覆盖、证据新鲜度、演化趋势和缺口原因五类对齐字段。
  - 以“保存探索/保存筛选条件”作为后续接口 mock：即便后端尚未接入，也在页面中展示已保存视图、最近使用和分享状态。
- 风险/不应照搬：Object Explorer 的 SQL/Action 能力需要完整权限和数据平台支持。前端先做可发现的筛选、比较和保存状态，不要伪造已经执行了真实写入或生产动作。

## 跨产品归纳：本项目建议采用的设计基线

### 1. 信息架构

- 一级导航：岗位发现、能力图谱、岗位演化、人岗诊断；二级导航：数据治理、评测中心、保存视图/任务队列。
- 壳层保持 Header + Sider + Content；图谱和诊断详情使用抽屉或右栏承载上下文，不把所有内容塞进 Card。
- 全局筛选只保留高频维度：时间范围、行业/岗位族群、数据来源、地区；其余条件放页内筛选。

### 2. 色彩和字体

- 底色以冷中性灰白为主，面板用白色，边框使用低对比灰；深色只用于导航和图谱控制区，避免大面积高饱和绿。
- 主行动色建议低饱和青绿/青蓝二选一；风险使用珊瑚红，待处理使用琥珀色，信息/选中使用靛蓝。所有色彩都通过 token 管理。
- 中文正文优先系统无衬线字体；标题使用较紧的字重和明确层级，不用超大装饰性数字。治理表 13--14px，普通正文 14px，页标题 24--30px。

### 3. 密度和组件

- 首页：少量结论型指标 + 趋势/异常 + 下一步动作；不做四个空洞大卡片。
- 表格：工具栏、筛选、列设置、批量操作、分页、行展开、空/错/加载状态必须成套实现。
- 图谱：画布、控制面板、详情抽屉、图例、适配视图和状态提示优先；节点颜色和大小的含义固定且可解释。
- 交互：所有“查看明细/打开图谱/进入审核/保存视图”都预留接口和 mock 反馈，按钮状态要能体现 loading、成功、失败。

### 4. 对当前前端的改版验收标准

- 首屏一眼能判断：当前模块、数据时间、待处理数量、最重要异常和下一步动作。
- 任何页面从 1440px 缩到 390px 不出现横向挤压；侧栏在小屏幕以覆盖层打开，内容区保持全宽。
- 同一对象（岗位/能力/证据）在列表、图谱、诊断和治理页使用同一名称、标签和颜色语义。
- 颜色不是唯一状态线索；图例、文字和图标同步表达。
- 页面中同时出现的强调色不超过 3 种；卡片圆角不超过 8px，避免渐变和装饰性光晕。
