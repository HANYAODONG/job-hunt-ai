# 第三阶段工作流分工

## 1. 本阶段定位

第三阶段承接第二阶段的模块开发结果，核心目标不是继续新增大量功能，而是把已经完成的工作流串成一条稳定可运行的主链路。

上一阶段各同学已经分别推进了：

- 标准数据集转换与字段契约。
- BM25 候选召回。
- text2vec/BGE 语义重排。
- 技能词典、技能抽取与知识图谱分析接口。
- 融合排序、解释模板和前端展示页面。

第三阶段要解决的问题是：

```text
各模块单独能跑
  -> 统一输入输出字段
  -> 串联成完整推荐链路
  -> 在真实标准数据上跑通
  -> 输出可解释推荐结果
  -> 形成可复现实验与演示版本
```

本阶段不建议再各自扩展大范围新功能，优先保证主流程可用、可测、可展示。

## 2. 第三阶段总目标

本轮结束时，项目至少应跑通下面这条链路：

```text
database 原始数据
  -> scripts/dataset_adapter.py
  -> artifacts/dataset_iteration_05/jobs.jsonl
  -> artifacts/dataset_iteration_05/candidate_profiles.jsonl
  -> BM25 TopK 候选召回
  -> text2vec/BGE 语义重排
  -> 技能覆盖率与知识图谱特征
  -> 融合排序 final_score
  -> 前端展示推荐岗位、分项得分和解释
  -> 评估脚本输出 Recall@K / MRR / NDCG
```

本阶段统一数据版本暂定为：

- 标准岗位：`artifacts/dataset_iteration_05/jobs.jsonl`
- 标准简历：`artifacts/dataset_iteration_05/candidate_profiles.jsonl`
- 金标标签：`artifacts/dataset_iteration_05/label_pairs_gold.jsonl`
- 银标标签：`artifacts/dataset_iteration_05/label_pairs_silver.jsonl`

注意：`artifacts/` 下面的文件默认是本地生成产物，仓库中只保留目录说明和必要样例，不提交大规模运行结果。

## 3. 工作流 1：数据契约、标签适配与统一评估

负责人：韩耀栋

### 本轮目标

把全组使用的数据入口、ID 规则和评估方式稳定下来，避免后续出现“这个模块能跑，但字段对不上”的问题。

### 主要任务

1. 维护 `scripts/dataset_adapter.py`，确保可以从 `database/` 中原始数据生成标准产物。
2. 明确 `candidate_id`、`job_id` 的唯一规则，避免旧标签 ID 和新岗位 ID 不一致导致评估全为 0。
3. 维护 `docs/data-schema.md` 和 `docs/workflow-1-standard-dataset-usage.md`。
4. 为其他工作流提供一份小规模 sample 数据，用于低配置电脑快速测试。
5. 汇总各模块输出结果，统一跑 Recall@K、MRR、NDCG 等指标。
6. 记录本轮联调问题、修复方式和最终可复现命令。

### 输入

- `database/job_bigcompany_final.csv`
- `database/government_jobs_2026_tech_filtered.csv`
- `database/synthetic_detailed_resumes_experience_30k.csv`
- `database/standard_job_title_dictionary.csv`
- 金标/银标文件

### 输出

- `artifacts/dataset_iteration_05/jobs.jsonl`
- `artifacts/dataset_iteration_05/candidate_profiles.jsonl`
- `artifacts/dataset_iteration_05/label_pairs_gold.jsonl`
- `artifacts/dataset_iteration_05/label_pairs_silver.jsonl`
- `artifacts/dataset_iteration_05/sample_pack/`
- 统一评估报告

### 验收标准

- 数据适配脚本一条命令可复现。
- 金标和银标中的 `candidate_id`、`job_id` 在标准数据中都能找到。
- 其他同学可以直接读取标准产物，不需要再自行改字段。
- 能对 BM25、语义重排、融合排序输出统一评估结果。

## 4. 工作流 2：语义重排服务联调

负责人：叶骑瑞

### 本轮目标

将 text2vec/BGE 语义重排从离线脚本推进到可被主链路稳定调用的模块。

### 主要任务

1. 读取工作流 1 输出的标准 `jobs.jsonl` 和 `candidate_profiles.jsonl`。
2. 读取工作流 5 的 BM25 TopK 候选集，只对候选集做重排，不直接扫描全量岗位。
3. 输出统一格式的 `semantic_score` 和 `semantic_rank`。
4. 保留轻量 text2vec 方案作为默认可运行方案。
5. BGE-M3 作为增强方案或对照实验，不强制所有成员本地运行。
6. 增加小样本运行参数，方便低配置电脑测试。

### 输入

- 标准岗位和简历文件。
- BM25 候选集。

### 输出

```json
{
  "query_id": "resume_000001_exp00_0",
  "candidates": [
    {
      "job_id": "JOB12214",
      "semantic_score": 0.82,
      "semantic_rank": 1
    }
  ]
}
```

### 验收标准

- 能在 sample 数据上快速跑通。
- 能在标准数据上完成候选集重排。
- 输出 ID 与工作流 1、工作流 5 保持一致。
- 能提供 BM25 only 与 BM25 + semantic 的指标对比。

## 5. 工作流 3：技能抽取、知识图谱特征与解释证据

负责人：魏昊朗

### 本轮目标

将技能抽取和知识图谱从“单独分析能力”接入推荐链路，输出可被融合排序和前端解释使用的特征。

### 主要任务

1. 继续维护 `standard_skill_dictionary.csv`，补充技能别名和标准技能名。
2. 对岗位和简历分别抽取标准技能。
3. 输出技能覆盖率、缺失技能、岗位族一致性和图谱相关度。
4. 保证知识图谱接口不只用于可视化，也能提供排序特征。
5. 输出解释证据，例如匹配了哪些技能、缺少哪些关键技能、哪些技能属于相关技能。

### 输入

- 标准岗位和简历文件。
- 标准技能词典。
- 岗位族/岗位标准化结果。

### 输出

```json
{
  "query_id": "resume_000001_exp00_0",
  "job_id": "JOB12214",
  "matched_skills": ["Python", "SQL"],
  "missing_skills": ["PyTorch"],
  "skill_coverage": 0.67,
  "job_family_match": 1.0,
  "graph_relatedness": 0.72,
  "evidence_paths": []
}
```

### 验收标准

- 技能抽取结果能覆盖主流岗位技能。
- 输出字段能被工作流 4 直接读取。
- 缺失技能和匹配技能能在前端解释中展示。
- Neo4j 图谱导入脚本可复现。

## 6. 工作流 4：融合排序、解释模板与前端联调

负责人：纪雨涵

### 本轮目标

把 BM25、语义重排、技能/图谱特征融合成最终推荐结果，并让前端展示真实链路结果。

### 主要任务

1. 读取 BM25 候选集、语义重排结果和知识图谱特征。
2. 实现可解释的加权融合排序。
3. 输出 `final_score`、分项得分和推荐理由。
4. 前端展示真实推荐结果，不再默认依赖固定 Mock 数据。
5. 处理缺失字段和异常结果，保证页面不会空白或崩溃。
6. 增加“Demo 模式”和“真实数据模式”的明确区分。

### 初始融合公式

```text
final_score =
  w1 * bm25_score
  + w2 * semantic_score
  + w3 * skill_coverage
  + w4 * job_family_match
  + w5 * graph_relatedness
```

权重第一版先手工设定，后续根据金标评估结果调整。

### 输出

```json
{
  "query_id": "resume_000001_exp00_0",
  "job_id": "JOB12214",
  "final_score": 0.83,
  "score_breakdown": {
    "bm25_score": 0.71,
    "semantic_score": 0.84,
    "skill_coverage": 0.76,
    "job_family_match": 1.0,
    "graph_relatedness": 0.68
  },
  "explanation": {
    "matched_skills": ["Python", "SQL"],
    "missing_skills": ["PyTorch"],
    "reason": "该岗位与候选人的后端开发和数据处理经历较匹配，但深度学习框架经验仍有缺口。"
  }
}
```

### 验收标准

- 前端可以展示真实接口返回的 TopN 推荐。
- 每个推荐岗位都有分项得分和解释。
- 没有数据时显示明确提示，而不是空白页面。
- 与 BM25 only、semantic only 能进行消融对比。

## 7. 工作流 5：BM25 召回、Elasticsearch 索引与候选集服务

### 本轮目标

稳定 BM25 召回服务，为语义重排、LLM 标注和融合排序提供统一候选集。

### 主要任务

1. 从标准 `jobs.jsonl` 构建 Elasticsearch 索引。
2. 明确索引字段权重，例如岗位标题、标准岗位、职责、要求、技能。
3. 为标准简历或用户查询返回 TopK 候选岗位。
4. 输出统一格式的 `bm25_score` 和 `bm25_rank`。
5. 支持小样本索引和全量索引两种模式。
6. 记录索引重建和查询命令。

### 输出

```json
{
  "query_id": "resume_000001_exp00_0",
  "candidates": [
    {
      "job_id": "JOB12214",
      "bm25_score": 13.52,
      "bm25_rank": 1
    }
```

- Elasticsearch 索引可从零重建。
- 任意标准简历可以返回稳定 TopK 候选岗位。
- `job_id` 与标准数据保持一致。
- 候选集能被工作流 2 和工作流 4 直接读取。

## 8. 第三阶段接口约定

本阶段所有工作流必须遵守：

1. 不自行改公共字段名。
2. 不自行生成另一套 `candidate_id` 或 `job_id`。
3. 中间产物统一放在 `artifacts/对应模块目录/`。
4. 大规模生成产物不直接提交到仓库。
5. 必须提供小样本运行方式。
6. 修改公共数据结构前，先同步更新 `docs/data-schema.md`。

建议的产物目录：

```text
artifacts/
  dataset_iteration_05/
  bm25/
  semantic_text2vec/
  semantic_bge/
  skill_graph/
  fusion_ranking/
  evaluation/
```

各目录中建议保留一个 `README.md`，说明本地部署时应该包含哪些文件、由哪个脚本生成、是否需要提交到仓库。

## 9. 第三阶段联调顺序

建议按下面顺序推进，减少互相等待：

```text
第 1 步：工作流 1 固定标准数据和 sample 数据
第 2 步：工作流 5 基于 sample 数据建立 BM25 候选集
第 3 步：工作流 2 对 BM25 候选集做语义重排
第 4 步：工作流 3 对同一批候选集输出技能和图谱特征
第 5 步：工作流 4 融合所有分数并接前端展示
第 6 步：工作流 1 汇总指标，形成第三阶段评估报告
```

如果全量数据跑不动，先统一使用 sample 数据联调。小样本链路跑通后，再逐步扩大数据规模。

本轮结束时，至少需要交付：

- 一条可以从标准数据到前端展示的完整链路。

## 11. 本阶段风险点

### 1. ID 不一致

这是当前最容易导致评估结果全为 0 的问题。所有模块必须使用工作流 1 输出的标准 ID。

### 2. 本地配置差异

不同成员电脑性能不同，所有脚本必须支持 sample 模式，不能默认要求全量 embedding 或全量图谱。

### 3. 生成产物误提交

`artifacts/` 中的大规模数据、`.npy` 向量、排序结果、临时 CSV 默认不上传仓库。需要共享时，优先说明生成命令或单独传压缩包。

### 4. Mock 数据残留

Mock 页面可以保留用于演示 UI，但真实链路必须有明确入口，不能让用户误以为 Mock 结果是算法真实输出。

### 5. 知识图谱只停留在可视化

本阶段知识图谱必须至少输出一种排序或解释可用特征，例如 `skill_coverage`、`missing_skills`、`graph_relatedness`，否则它对主链路贡献不足。

## 12. 第三阶段完成标志

当满足下面条件时，可以进入第四阶段：

1. 五个工作流都能读取统一标准数据。
2. BM25、语义重排、技能图谱和融合排序能在 sample 数据上串通。
3. 前端可以展示真实推荐结果和解释。
4. 至少完成一次指标评估。
5. 每个模块都有清楚的运行命令和输出说明。

第四阶段再重点做：

- 企业评分标准对齐。
- 权重调优。
- 消融实验。
- 论文/答辩材料中的实验结果整理。
- 演示流程打磨。
